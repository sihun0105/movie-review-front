# 공개 페이지 검색 수집 개선

## 운영에서 확인한 사실

- `/articles/5`: HTTP 200, 고유 제목/H1/본문, self canonical, index/follow 정상.
- `/sitemaps/articles/1`에 해당 글 포함. 사이트맵 누락이 원인은 아님.
- `/articles`: 원본 HTML은 loading만 표시하고 개별 글 링크가 없음.
- `/movie/20250654`: 메타데이터는 있지만 제목/H1/줄거리/감독 본문은 클라이언트 조회 이후 표시.
- `/match/{id}`, `/chat/public`: 홈 canonical을 상속함.
- 영화 사이트맵에 실제 수정일이 아닌 `2000-01-01` 이관용 날짜 포함.
- Search Console 접근 권한으로 URL 검사를 수행하지 않았으므로 실제 색인 제외 사유는 미확인.

## 변경

- 커뮤니티 첫 화면과 페이지별 목록을 서버 데이터로 렌더링. 기존 무한 스크롤 유지.
- 이전/다음 HTML 링크와 페이지별 canonical로 뒤쪽 글도 발견 가능하게 연결.
- 홈에 최신 게시글 링크 추가. 제목/본문을 검색용으로 임의 변경하지 않음.
- 영화 본문/출연진/첫 댓글을 서버에서 전달하고 SWR로 재검증.
- 메타데이터와 본문의 영화 조회를 요청 단위로 공유. 첫 댓글 페이지를 1이 아닌 0으로 수정.
- 댓글 서버 조회 실패는 영화 본문을 막지 않음. 실제 실패 시 클라이언트 재시도 유지.
- 매칭 상세 공개 본문 서버 렌더링 및 개별 canonical. 세션 확인 전 신청 실행 차단 유지.
- 매칭 목록 첫 페이지를 서버 렌더링. 개인 필터는 서버의 공개 fallback에서 제외.
- 공개채팅 self canonical 및 고유 제목/설명.
- 임시 수정일과 요청 당일을 수정일로 표현하던 메타데이터 제거.
- 게시글 API 일시 장애를 삭제(404)/noindex로 바꾸지 않고 실제 오류로 전달.

## 재검증

```bash
pnpm verify --build
node scripts/check-public-seo.mjs https://bollae.kr 5 20250654
```

스크립트는 브라우저 JS를 실행하지 않은 HTML을 파싱해 제목, 링크, canonical,
robots, 사이트맵을 검사한다. 기본 글 ID는 홈/목록 첫 페이지에 있는 공개 글이어야 한다.
색인 여부나 검색 순위를 판정하는 스크립트가 아니다.

## Search Console에서 확인할 항목

1. `https://bollae.kr/articles/5` URL 검사: 색인 상태, 최근 크롤링, Google이 선택한 canonical.
2. 실제 URL 테스트로 배포된 페이지 확인 후 해당 URL 색인 생성 요청.
3. Sitemaps에서 `https://bollae.kr/sitemap.xml`의 성공/최근 읽은 날짜 확인.
4. 다른 공개 영화/게시글도 동일한 URL 검사로 제외 사유를 구분.

기존 글은 짧은 감상과 이미지 중심이다. 독창적인 감상, 구체적인 장면 해석,
추천 대상 등 실제 작성자의 경험을 보강하면 독자에게 도움이 된다. 자동으로
내용을 늘리거나 키워드를 반복하는 것으로 순위를 보장할 수 없다.

근거: [Google 기술 요구사항](https://developers.google.com/search/docs/essentials/technical),
[사이트맵 안내](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap),
[재크롤링 요청](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl).
사이트맵 제출과 기술 요건 충족은 색인/검색 순위를 보장하지 않는다.
