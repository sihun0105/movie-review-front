# Account Activity Lists Design

## Goal

마이페이지의 네 가지 활동 숫자를 한 줄 탐색 요소로 바꾸고, 선택한 활동의 상세 목록과 삭제 기능을 같은 화면에서 제공한다.

## UX

- 별도 섹션 제목 없이 `작성 댓글`, `영화 평가`, `작성 게시글`, `받은 좋아요`를 4열 한 줄로 표시한다.
- 각 항목은 버튼이며 숫자와 라벨을 함께 보여준다. 선택 항목은 명확한 배경색과 `aria-pressed`로 구분한다.
- 선택 전에는 목록을 노출하지 않는다. 선택하면 바로 아래에 최대 10개를 불러오고, 다음 페이지가 있으면 `더 보기`를 제공한다.
- 댓글은 `게시글 제목 > 댓글 내용`, 평점은 포스터·영화 제목·별점, 게시글은 제목·작성일·반응 정보, 받은 좋아요는 게시글 제목·좋아요 수를 보여준다.
- 댓글·평점·게시글 삭제는 확인 다이얼로그 후 실행한다. 성공하면 목록과 상단 숫자를 동시에 갱신한다.
- 받은 좋아요 목록은 삭제 기능 없이 해당 게시글 이동만 제공한다.

## API

- `GET /user/activity/:type?page=1&pageSize=10`에서 인증 사용자의 `comments`, `ratings`, `articles`, `likes` 목록을 반환한다.
- 삭제되었거나 삭제된 부모 콘텐츠에 속한 데이터는 제외한다.
- `DELETE /user/activity/ratings/:movieCd`는 인증 사용자의 평점을 soft delete한다.
- 댓글과 게시글 삭제는 기존 아티클 API를 재사용한다.
- 평점을 다시 등록하면 `deletedAt`을 `null`로 복원하고, 평점 조회와 평균 집계는 삭제된 평점을 제외한다.

## Boundaries

- API Gateway의 기존 `UserActivityService`가 활동 집계와 목록 조회를 담당한다.
- 프론트는 기존 `user-activity` 파사드와 Next BFF를 확장하며 브라우저에서 백엔드 주소나 토큰을 직접 사용하지 않는다.
- 각 타입은 명시적인 discriminated union으로 모델링해 목록 렌더링과 삭제 대상을 안전하게 분리한다.

## Error Handling And Tests

- 인증 만료는 다시 로그인 링크, 일반 실패는 재시도 버튼을 제공한다.
- 개별 삭제 실패는 목록을 유지하고 사용자에게 오류를 표시한다.
- Backend Jest로 조회 필터·페이지네이션·평점 soft delete와 재활성화를 검증한다.
- Frontend Vitest로 BFF 인증 전달, UI 4열/선택/삭제 계약, 데이터소스 요청을 검증한다.
